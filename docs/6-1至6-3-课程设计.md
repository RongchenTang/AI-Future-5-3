## 2. 第 12 次课（6-1）：从本地到网上，从想法到立项

### 流程（90′）
| 环节 | 时长 | 内容 |
|---|---|---|
| 为什么别人打不开？ | 15′ | 把 localhost 链接发到班群，全班都打不开；三种地址：`file:///`（抽屉里的纸）、`localhost`（「我家」）、公开网址（有门牌号）；网址的组成（协议、域名、路径）；部署 = 把文件放到一台一直开着、有公开地址的电脑上；域名 = 门牌号 |
| 部署作业说明 | 5′ | GitHub 网页上传路线；部署求助提示词；成功标准：同学用手机流量能打开；上线前隐私自查 |
| 看看别人用 AI 做了什么 | 12′ | 按网页工具 / 小游戏 / 智能体 / 手机网页分类；包括老师自己用 AI 做的职业之书与课件 |
| MVP 三层分类 | 5′ | 必须有 / 可以有 / 暂时不做；一人组的「必须有」只放一个功能 |
| 头脑风暴 + 分组 | 30′ | 个人写 1–2 个痛点 → 投票 → 围绕点子组队（1 班老师分组）；可用「项目灵感抽卡」：谁 × 什么场景的麻烦 × 做成什么 |
| 一分钟立项 | 15′ | 每组约 1.5 分钟，按立项卡讲 |
| 作业 | 5′ | ① 部署个人网站（5-3 作业）② 写项目书 |

### 立项卡（6 行）
项目名 / 一句话介绍 / 给谁用 / 解决什么麻烦 / 做成什么形式 / 第一版最少能做到什么

### 部署兜底
5-3 作业截止在 13 次课前。部署实在不成功的同学：13 次课前开放 10 分钟答疑，或允许提交本地文件夹 + 录屏（规则待老师确定）。

### 待做材料
- 课件（沿用手账风，可换强调色区分新章节）
- 网址小测：「这个网址能发给同学吗？」
- 部署指引（GitHub 网页上传 + Pages）与部署求助提示词
- 项目灵感抽卡
- 立项卡（填写后可投屏）
- 项目书模板（Markdown）：项目名与一句话介绍、目标用户、真实痛点、使用场景、功能三层分类、MVP（第一版必须跑通的一条路径）、验收标准、分工、13 次课开发计划

## 3. 第 13 次课（6-2）：做出 MVP

| 环节 | 时长 | 内容 |
|---|---|---|
| MVP 复述 | 8′ | 各组用三层分类复述自己的 MVP |
| 从项目书到开发提示词 | 6′ | 把 MVP 拆成一步步的任务，一次只让 AI 做一个功能 |
| 开发节奏 | 4′ | 描述 → 生成 → 运行 → 看 → 改 |
| AI 改坏了怎么办 + Git 与 GitHub | 10′ | 每做通一个功能就存档；Git 是「能记住每一次修改的存档」；提交、回退；衔接 12 次课的网页上传 |
| API Key 再强调 | 2′ | 不能写进纯网页代码 |
| 小组开发 | 50′ | 老师巡视；同一时间只让一个人改代码，其他人负责素材、文案、测试、记录 |
| 进度检查 + 作业 | 10′ | 课后完成 MVP 并部署，带链接来 14 次课；保留开发记录 |

出错时问 AI 的方法：现象—期望—位置—验证；F12 看报错。
讲方法，不讲具体工具的按钮（工具不限）。

## 4. 第 14 次课（6-3）：交换测试

沿用原教案的设计（MVP 验收、测试方法、电脑端与手机端测试、汇总反馈、AI 辅助修改、一分钟迭代汇报），补充三张表：

| 表 | 填写人 | 内容 |
|---|---|---|
| 测试任务卡 | 被测组（课前写好） | 3 个「请你完成……」的任务；测试时被测组不许解释、不许帮忙 |
| 测试记录单 | 测试组 | 任务 / 是否完成 / 卡在哪里 / 截图 / 严重程度（阻断·影响·建议）/ 设备（电脑·手机） |
| 反馈卡 | 测试组 | 两颗星一个愿望：两个做得好的地方 + 一个最重要的建议 |

- 交换方式：环形交换（A 测 B，B 测 C……），每组既测试别人也被测试；老师巡回参与各组测试。
- 分享：每组 1 分钟，「我们测了 X 组：最好的一点是……，最大的问题是……，建议……」。
- 收尾：每组当堂修复最严重的 1 个问题并复测。
